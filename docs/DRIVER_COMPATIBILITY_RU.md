# Что заменено, а что ещё донорское: DBY-W09 VD

Точная модель владельца: **DBY-W09**. Его оригинальная прошивка определила активный DTBO index **3** = **DBY_W09_VD**. Это **не** `DBY_W09_VG` из публичного Linux-порта.

## Матрица совместимости

| Компонент | Статус в новом CI | Что ещё требуется для настоящего UEFI |
|---|---|---|
| AArch64 firmware core / KonaPkg | Компилируется | Проверить раннюю инициализацию, память, UART и аппаратную загрузку |
| Memory map (DRAM + protected) | Кандидат от DBY-W09, автоматическая проверка DTB/iomem | Верификация бездоступных диапазонов TZ/DDR на реальном оборудовании |
| Board-ID / rootparam DTBO | **Собственный минимальный вариант VD**, dtc + fdtget проверены | Полный DTBO с драйверными OEM фрагментами, проверка совместимости с Huawei ABL |
| DSDT (ACPI) | **Собственный диагностический пустой DSDT**, IASL 0 errors | Написать устройства, _CRS, GIC/IORT, DMA, питание, UFS, USB, экран |
| Общие SM8250 ACPI (APIC/FACP/IORT/GTDT) | Из SurfaceDuoACPI, не адаптированы | Сопоставить контроллеры и топологию DRAM/IRQ с DBY-W09 |
| Qualcomm UEFI DXE драйверы | **По-прежнему заимствованы из qcom-mtp8250** | Получить/адаптировать соответствующие компоненты для Huawei, проверить PMIC и TZ |
| USB-C (DWC3) | На Android `a600000.dwc3`; UEFI donor | Питание, Type-C и USB init; различия GPIO/PMIC |
| UFS storage | На Android `soc/1d84000.ufshc`; UEFI donor | Контроллер, IOMMU, тактирование/питание, безопасный доступ |
| MIPI-DSI/экран | Android панель `lcd_kit_debussy_190_20d_10p9_qcom` | Настоящий Framebuffer/GOP и безопасная подсветка; не копировать конфигурацию `debussy_110` |
| GPU/Wi-Fi/Touch | Не работают в UEFI-порте / Windows-проверок нет | Корректные ACPI описания и совместимые Windows ARM64 драйверы |

## Почему пока нельзя прошивать

В GitHub Actions создаётся UEFI firmware volume `.fd`, но **пустой DSDT сознательно скрывает периферию, а OEM-компоненты donor qcom-mtp8250 могут обратиться к неправильным MMIO/GPIO**. Никаких испытаний на планшете не было.

Прежний тест `fastboot boot` уже приводил к ошибке `Load Error`, после чего возникли проблемы с запуском Android. **Не повторять этот эксперимент с текущим FD.**

Ни `fastboot flash`, ни `dd`, ни изменение `abl`, `xbl`, `boot`, `dtbo` в этих CI-инструкциях не предусмотрены.

## Дальше

2. Построить полноценный таблицы ACPI для реального Windows ARM64 (не стихийный перенос Linux DTS в AML).
3. Подготовить диагностический BootShim и восстановление с известной рабочей резервной копией; только после анализа Huawei ABL.
