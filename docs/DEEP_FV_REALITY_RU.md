# Глубокая проверка экспериментального DBY-W09 KonaPkg

**Основа:** полная EDK2 сборка GitHub Actions №43289204389, плата пользователя DBY-W09, аппаратный DTBO №3 `DBY_W09_VD`.

## Что реально находится внутри

Проверен локальный артефакт `DBY_W09_KonaPkg_AUDITED_v4.zip` (без перепрошивки):
- Файл `SM8250_EFI.fd` под именем `DBY-W09-COMPILE-ONLY-NOT-FLASHABLE.fd` — 2 879 488 байт.
- SHA256: `8350e1416687c4dc1db84a7c0ba612fe05018a739739d72ac213e51d5a50f268`.
- Внешний Firmware Volume: 3 FFS; 16-битная контрольная сумма заголовка проверена.
- Одна GUID-defined `LZMA` секция содержит вложенный FV размером 10 952 704 байта; заголовок и checksum проверены.
- Вложенный FV содержит 165 FFS (в том числе FFS_PAD), **124 DXE-драйвера**, **6 UEFI_APPLICATION**, **131 PE32-модуль AArch64** и `EdkShell`.
- Прошлая проверка CI останавливалась на внешнем FV; новый `tools/verify_nested_fv.py` проверяет всю вложенную структуру и отказывает, если Shell отсутствует, неверная архитектура или нарушен checksum. Важно: Type 0x0B означает `FV_IMAGE`, а не тип DXE-драйвера.

## Сопоставление заводских модулей

Сравнили только **локальную** копию оригинального XBL владельца и собранный nested FV, без публикации заводских .efi.

| Метрика | Результат |
|---|---:|
| Оригинальных PE32 EFI (AArch64) | 89 |
| Совпало GUID заводского файла с прошивкой KonaPkg | 71 |
| Без соответствующего GUID в сборке | 18 |
| Полностью идентичные PE32 коды среди этих 71 | 0 |

**Ноль идентичных PE-кодов не равен нулю совместимых драйверов:** отсутствие побайтового совпадения выявляет различия сборок; оно само по себе не доказывает функциональную несовместимость.

Критичная особенность: заводской `DisplayDxe` не найден по GUID в прошивке. Донорские графические компоненты могут не инициализировать панель `lcd_kit_debussy_190_20d_10p9_qcom`.

## Что компиляция не проверяет

1. Неизвестен корректный метод передать управление EDK2 от Huawei ABL; `fastboot boot` уже выдавал `Load Error`.
2. Донорские QCOM DXE не проходили испытания на конкретном DBY-W09; TrustZone/PMIC/clocking вызывают риск зависания.
3. DSDT заглушка, а не полноценный ACPI для Windows ARM64.
4. DTBO пока `rootparam`-only, а не полная аппаратная OEM-конфигурация.
5. Не проверен GOP/экран, USB, UFS, питание и путь восстановления после UEFI-старта.

Никаких безопасных оснований считать `.fd` прошиваемым нет. **Ни при каких обстоятельствах не заменять им `boot`, `abl`, `xbl` или `dtbo`.**

## Воспроизведение

GitHub Actions `FULL KonaPkg compile` теперь запускает `tools/verify_fv.py` и `tools/verify_nested_fv.py`. На успешной сборке загружается `nested-fv-audit.json` в том же артефакте, что и `.fd`.
